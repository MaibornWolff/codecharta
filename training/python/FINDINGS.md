# Python

## Project
- Layout: flat package layout, `de/sots/cellarsandcentaurs/{domain/model,domain/service,adapter/persistence,application,application/dto}` directly under the language folder, `tests/test_creature_service.py` (pytest) beside it. 33 `.py` files, 8 of them empty `__init__.py` package markers, 24 non-test source files with content plus the test file. Based on `Ideas/DC/DependaCharta/exampleProjects/PythonExample`, but without its `src/` folder (see "src layout" below for why).
- Casing: `snake_case` modules and functions, `PascalCase` classes, `SCREAMING_SNAKE` constants. Barrel = `domain/model/__init__.py` and `application/__init__.py` with `__all__`; `application/dto/__init__.py` re-exports the DTO.
- Stress constructs the language has: aliased import (`from .creature_entity import CreatureEntity as Entity`), wildcard import (`from ...domain.model import *`), barrel re-export (`__init__.py`), inheritance (`Centaur(Creature)`), ABC as interface (`Creature(Fightable)`, `PersistedCreatures(Creatures)`), generic base (`Repository(ABC, Generic[T])`, `CreatureRepository(Repository[Entity])`), type-position-only use (`CreatureId` under `TYPE_CHECKING` with `from __future__ import annotations` in `creature_service.py`), instantiation only (`CreatureEntity(...)` in `persisted_creatures.py`), static member only (`CreatureFacade.STANDARD_CREATURE_TYPE`), decorator only (`@traced` from `application/tracing.py` on `CreatureFacade.create`), same simple name (`domain.model.creature.Creature` and `application.dto.creature.Creature`, both used in `creature_facade.py`, the DTO aliased `as CreatureDto`), unused import (`Fightable` in `creature_util.py`), stdlib and third-party (`uuid`, `logging`, `typing`, `dataclasses`, `enum`, `abc`, `random`, `functools`, `pytest`, `unittest.mock`), test file, two declarations plus a free function in one file (`dice.py`: `Dice`, `DiceRoll`, `roll_d20`), file name differing from the declaration (`errors.py` holds `NoSuchCreatureException`), relative module import (`from ..model import creature` then `creature.Creature`).
- Stress constructs the language does not have: a fully qualified reference **without** an import (Python needs `import de.sots.cellarsandcentaurs.domain.model.speed`; the facade then uses `de.sots.cellarsandcentaurs.domain.model.speed.Speed(...)`, which is the closest Python gets); annotations/attributes as a separate concept (decorators are the equivalent); block comments (Python has only `#` line comments and docstrings, the "block comment" in `CreatureUtil` is a function docstring); a syntactic `interface`/`enum` keyword (ABC and `Enum` subclasses instead).
- Identifier forms: `walking_speed` (facade parameter), `walkingSpeed` (test file, since Python is a snake_case language), `MAX_HIT_POINTS` (`hit_points.py`), `ArmorClass`, `xp_value` (`Creature.gain_xp_value(self, xp_value)`), `d20Roll` (local in `roll_d20`), `"centaur-stable"` (`CreatureFacade.STABLE_NAME`).

- False positives: none at file level (51 found vs. 52 expected, the one difference is the missing DTO edge). At leaf level the only noise is the `VARIABLE` leaves and their intra-file edges listed under 10.
- Cycles: expected `creature -> application/__init__ -> creature_facade -> creature_service -> creature` (plus the short cut `creature_facade -> creature`, and `creature_service -> creatures -> creature`) are all flagged. Expected `armor_class -> creature_util -> domain/model/__init__ -> armor_class`: `armor_class -> creature_util` and `creature_util -> domain/model/__init__` are flagged, but **`domain/model/__init__.py -> armor_class.py` is not**, although it closes that file-level cycle (only the longer route `domain/model/__init__ -> creature.py` is flagged). Cause: cycles are detected between leaves, and the re-export leaf `__init__.ArmorClass` lies on no leaf cycle; the file flag is the aggregation of its leaf flags, so a cycle that only exists at file level is invisible. 12 edges flagged in total.
- Upward edges: `armor_class -> creature_util` and `creature -> application/__init__` are `isPointingUpwards` (expected). `persisted_creatures -> application/__init__` is not, because `adapter` (level 2) is levelized above `application` (level 1) above `domain` (level 0), which is the intended layering.
- Leaf kinds: `CLASS` for every class, including the `Enum` subclasses `CreatureType`/`SpeedType` (should be `ENUM`) and the ABCs `Fightable`, `Creatures`, `Repository` (should be `INTERFACE`); `FUNCTION` for `roll_d20`, `traced`, the test functions; `UNKNOWN` for all `__init__.py` re-export leaves (`application.__init__.CreatureFacade`, the 12 `domain.model.__init__.*`, `dto.__init__.Creature`) which should be `REEXPORT`; `VARIABLE` for module-level assignments (`logger`, `__all__`, `T`, `MAX_HIT_POINTS`). Kinds are therefore too coarse but never wrong for the language, since Python has no enum/interface syntax. Leaf edge `usage` is always `usage`.
- Native vs. resolved: Python gives a module system (absolute and relative imports, `__init__.py` packages, `import ... as`, `from ... import *` with `__all__`), no compile-time types. The analyzer takes every identifier in a class/function body as a candidate type name and resolves it against a project-wide simple-name dictionary, disambiguated by the file's import paths; aliases are translated back to the imported name. Consequences seen here: (a) two types with the same simple name in one file collapse to one `usedType`, so only the first matching import wins (construct 7; a scratch variant with `from ...dto import creature as creature_dto` and `creature_dto.Creature(...)` found the DTO edge and then lost the domain `Creature` edge instead); (b) a module-level variable is treated as a declaration leaf; (c) the leaf path is derived from the physical path, not from the import path.
- **src layout**: the same project copied under `src/` (the layout of the DependaCharta `PythonExample` and of most modern Python packages) yields only 24 file edges instead of 51: every absolute `from de.sots.cellarsandcentaurs... import` is lost, because the leaves are named `src.de.sots...` while the import says `de.sots...`, and the suffix matching in `resolveComplexModuleImport` only fires when the import path is longer than the leaf's package, never when it is shorter. Only relative imports and `__init__` re-exports survive; all cycles and upward edges disappear.

## Domain language parser
- Command: `domainlanguageparser -nc ... -e "output,FINDINGS.md" -o output/domain.cc.json`, exit 0, no errors (`output/domain.stderr.log`). Extra runs in `output/variants/`: `--stop-word-level MINIMAL`, `--stop-word-level AGGRESSIVE`, `--exclude-tests`, and `--identifier-weight 1 --comment-weight 1 --string-weight 1` (weights must be positive, `0` is rejected).
- Expected words at the root node (90 words in total): all 17 present: creature(95), speed(38), hit(31), points(31), armor(22), roll(14), dice(12), damage(8), stable(7), centaur(6), treasure(5), hoard(5), dungeon(3), cellar(2), lair(2), initiative(2), encounter(2).
- Keyword leakage: none of the Python keywords or built-ins (`class`, `def`, `self`, `cls`, `init`, `id`, `type`, `str`, `int`, `dict`, `max`, `min`, `super`) appear, except that stdlib **decorator and helper names are counted as identifiers**: `dataclass(18)`, `abstractmethod(12)`, `classmethod(3)`, `property(3)`, `functools(3)`, `wrapper(3)`, `args(3)`, `kwargs(3)`, `function(3)`, `logger(9)`, `pytest(3)`. That is wrong for the language: `@dataclass`, `@abstractmethod`, `@classmethod`, `@property`, `*args`, `**kwargs` are boilerplate in almost every Python codebase and belong in `python-keywords.txt` (`staticmethod` is already there, `classmethod`/`property`/`dataclass`/`abstractmethod` are not). The numeric token `20(6)` from `roll_d20`/`d20Roll` is also noise.
- Technical stop words at MODERATE: `util`, `test`, `tests`, `mock`, `exception`, `service`, `save`, `find`, `get`, `create`, `base` are filtered as intended. Leaking: `repository(9)`, `entity(6)`, `facade(4)`, `persisted(3)`, `standard(6)`, `item(9)`, `key(9)`, `value(15)`, `one(3)`. `repository`/`entity`/`facade` are architectural pattern words in the sense of the MODERATE list (`manager`, `service`, `handler`, `controller`, `factory`, `builder` are listed, these three are not); AGGRESSIVE removes `entity`, `facade`, `repository`, `logger`, `value`, `args`, `function`. MINIMAL adds `base`, `create`, `find`, `get`, `save`, `service`.

## Verdict
- Good: 50 of the 52 expected file edges in round 1 and 5 of the 9 added in round 2 (56 of 61 in total), zero false positives, tests skipped by default and found with `--include-tests`, aliased/wildcard/barrel/relative-module/`TYPE_CHECKING`/decorator/generic/fully-qualified imports all resolved, main cycle and both upward edges flagged, unused import ignored, stdlib and third-party never appear. - Wrong: (1) `application/creature_facade.py`: two types named `Creature` in one file collapse to one edge, the DTO `application/dto/creature.py` edge is missing (with a module alias the domain edge is missing instead). (2) A `src/` layout loses every absolute import (51 -> 24 edges) because leaf paths are physical paths and the suffix match is one-directional. (3) `domain/model/__init__.py -> armor_class.py` is not flagged `isCyclic` although it closes a file-level cycle; cycle flags are leaf-level only. (4) Domain parser: stdlib decorators `dataclass`, `abstractmethod`, `classmethod`, `property` and `args`/`kwargs`/`functools`/`wrapper` are counted as domain words. (5) Domain parser: typed parameters with defaults (`typed_default_parameter`) are not extracted, so `description` in `armor_class.py` and the `Creature.__init__` parameters are silently absent. (6) Round 2, same root cause as (1): `application/encounter.py` imports `roll_d20` from `domain/model/dice.py` in `try:` and from `domain/model/fallback_dice.py` in `except ImportError:`; only the first import wins, the fallback edge is missing although an import inside `except` alone is resolved (scratch variant).

- Missing: leaf kinds `ENUM`, `INTERFACE` (ABC) and `REEXPORT` for `__init__.py` are not produced (everything is `CLASS`/`UNKNOWN`); leaf edge usage kinds (inheritance, implementation, type-only) are all `usage`; module-level assignments (`logger`, `__all__`, `TypeVar`) are reported as `VARIABLE` leaves, which is more noise than information; `repository`, `entity`, `facade` are not in the MODERATE technical stop-word list.
